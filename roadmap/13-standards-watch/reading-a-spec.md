# Reading a spec

**TL;DR:** IETF specifications use capitalized requirement words whose meanings are defined by
BCP 14. MUST, REQUIRED, and SHALL mark an absolute requirement. SHOULD marks a recommendation
that may be set aside only after understanding the consequences and having a valid reason. MAY
and OPTIONAL describe a feature an implementation may omit, so peers must tolerate either
choice except for the missing feature itself. When a specification invokes BCP 14, only
uppercase forms have these special meanings. The keywords identify requirement levels where
they appear, but they are not a complete conformance checklist; other normative definitions,
syntax, and referenced requirements still matter.

Uppercase MUST / SHOULD / MAY carry BCP 14's requirement meanings; lowercase forms are
ordinary prose.
